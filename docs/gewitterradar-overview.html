Gewitterradar

Live-Blitz- und Gewitterdarstellung für Home Assistant.

Gewitterradar verbindet Live-Blitze, Radien, Cluster, Kompass, Verlauf und weltweite Referenzorte in einer gemeinsamen Home-Assistant-Oberfläche. Native Integration und Dashboard-Karte sind zwei Auslieferungsformen desselben Produkts.

⚡ Datenquelle

Gewitterradar visualisiert Live-Blitze aus der Home-Assistant-Integration Blitzortung.org. Gewitterradar ersetzt Blitzortung.org nicht. Die Datenquelle muss vorhanden und funktionsfähig sein und bleibt Eigentümerin ihrer Datenregion und Abonnementlogik.

🧰 Installation · Native Integration

  1. Dieses Repository in HACS als benutzerdefiniertes Repository vom Typ Integration hinzufügen.
  2. Gewitterradar Integration installieren.
  3. Home Assistant vollständig neu starten, wenn dies verlangt wird.
  4. Einstellungen → Geräte & Dienste → Integration hinzufügen öffnen.
  5. Gewitterradar hinzufügen.
  6. Unter Einstellungen → Dashboards → Ressourcen die folgende Ressource als JavaScript-Modul registrieren:
/gewitterradar/gewitterradar.js

Eine frische native Installation benötigt kein YAML-Helferpaket.

🧩 Installation · Dashboard-Variante

  1. TheDaimos/gewitterradar-dashboard in HACS als Dashboard-Repository hinzufügen.
  2. Gewitterradar installieren.
  3. Ressource prüfen:
/hacsfiles/gewitterradar-dashboard/gewitterradar.js
  1. Das aktuelle Gewitterradar-Package aus dem HACS-Ordner nach /config/packages/ kopieren.
  2. Home Assistant vollständig neu starten.

Falls Packages noch nicht eingebunden sind:

homeassistant:
  packages: !include_dir_named packages

Nicht mehrere Gewitterradar-Packages mit denselben lightning_detection_*-Helfern parallel aktivieren.

🖥️ Gewitterradar-View anlegen

Weder die native Integration noch der Dashboard-Download erzeugen automatisch eine Dashboard-View.

Minimal:

type: custom:gewitterradar-card

Vollständiges Beispiel:

views:
  - title: Gewitterradar
    path: gewitterradar
    icon: mdi:weather-lightning
    type: panel
    cards:
      - type: custom:gewitterradar-card

Falls der Blitzortung-Zähler anders heißt:

type: custom:gewitterradar-card
counter_entity: sensor.DEIN_LIGHTNING_COUNTER

📍 Referenzstandort

Für weltweite Standortwechsel sollte Blitzortung.org den passenden Gewitterradar-Tracker als Location entity verwenden.

Native Integration

device_tracker.gewitterradar

Dashboard

device_tracker.gewitterradar_dashboard

🔁 Standortablauf

  1. Ort suchen oder Koordinaten übernehmen.
  2. Gewitterradar verschiebt seinen Referenztracker.
  3. Blitzortung.org erkennt die neue Position über die Location Entity.
  4. Neuabonnement und Datenlatenz bleiben Aufgabe der Blitzortung.org-Integration.

Gewitterradar verändert keine fremden Config Entries und schreibt nicht direkt in private Home-Assistant-.storage-Dateien.

🛡️ Recorder schützen

Bei hoher Blitzaktivität können sehr viele Zustandsänderungen entstehen. Kurzlebige Blitzentitäten sollten nicht dauerhaft gespeichert werden.

recorder:
  exclude:
    entity_globs:
      - "geo_location.lightning_strike*"
      - "sensor.*_lightning_distance"
      - "sensor.*_lightning_azimuth"
      - "sensor.*_lightning_counter"

Besteht bereits ein recorder:-Block, die Einträge dort ergänzen. Keinen zweiten Hauptschlüssel anlegen.

🧭 Ressourcenprüfung

Es darf genau eine Gewitterradar-JavaScript-Ressource aktiv sein.

Veraltete, parallele oder Test-Ressourcen entfernen. Nach Änderungen Browser bzw. Companion-App vollständig neu laden.

♻️ Bestehende Installationen & Migration

Beim ersten nativen Setup können unterstützte gültige lightning_detection_*-Legacy-Werte einmalig übernommen werden. Bereits vorhandene native Werte haben Vorrang; Legacy-Helfer werden nicht automatisch gelöscht.

  • nur ein Gewitterradar-Repository pro Auslieferungsform laden;
  • nur eine JavaScript-Ressource aktiv halten;
  • alte Packages deaktivieren, bevor das aktuelle Package aktiviert wird;
  • historische Registry-Objekte erst löschen, wenn sie sicher nicht mehr verwendet werden.

🔒 Qualität, Schutz & Releaseprozess

Native Integration und Dashboard müssen denselben Produktstand ausliefern. Geschützt sind insbesondere der akzeptierte „Über Gewitterradar“-Stand, der normale UI-/Funktionsstand, Diagnosefunktionen, Hi-Res-/Mastergrafiken sowie der PRE-MERGE-/Golden-Master-Prozess.

Die Release-Linie wird unter anderem über Home-Assistant-Laufzeittests, HACS/Hassfest, deterministisches Staging, Sprach-/Recorder-Audits, Browserregressionen, Golden-/Geometrievertrag, Diagnosevertrag und Hi-Res-Retentionsvertrag geprüft.
